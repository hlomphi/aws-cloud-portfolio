## Operating Rules

- Work autonomously within the approved task scope.
- Minimise unnecessary user intervention.
- Use British English.
- Maintain consistent formatting across all documentation.
- Do not fabricate achievements, qualifications or technical implementations.
- Flag missing or contradictory information for review.

## Confidentiality

- Never disclose client names.
- Never expose credentials, AWS account IDs, private endpoints or confidential business information.
- Use anonymised project titles and architecture diagrams.
- Never reproduce proprietary client source code.
- Use independently developed examples for technical demonstrations.
- Do not commit original confidential source documents.

## Case Study Standard

Each case study should include:

1. Executive overview
2. Business challenge
3. Solution architecture
4. Technical implementation
5. Personal responsibilities
6. Security and governance
7. Cost optimisation
8. Project outcomes
9. Architecture diagram
10. Technologies used
11. Lessons learned

## Accuracy Requirements

- Distinguish proposed architectures from deployed solutions.
- Identify proofs of concept.
- Distinguish projected savings from realised savings.
- Distinguish personal contributions from team achievements.
- Use supplied evidence for measurable outcomes.
- Do not assume that a planned implementation was completed.

## Architecture Diagrams

- Follow AWS architecture best practices.
- Clearly identify infrastructure components and data flows.
- Show security and network boundaries where relevant.
- Exclude sensitive infrastructure identifiers.
- Ensure diagrams match documented implementation status.

## Git Workflow

- Never commit directly to main.
- Create a dedicated branch for each approved work package.
- Batch related changes to minimise repetitive tasks.
- Validate Markdown, internal links and diagram references.
- Check all changes for confidential information.
- Create a pull request for human review when permissions allow.
- If pull request creation fails, provide the comparison URL.
- Never merge without explicit owner approval.

## Completion Report

For every completed work package, provide:

- Summary of changes
- Files modified or created
- Validation results
- Outstanding questions or risks
- Branch and pull request URL

The repository owner retains final approval authority.
